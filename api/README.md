# HTTP API

`openapi.yaml` описывает действующие маршруты, модели, проверку Bearer-токена сессии,
права редактора и ответы сервера. Формат — OpenAPI 3.0.3.

Go-сервер встраивает схему и Swagger UI в бинарник и открывает:

- `/docs` — интерактивную документацию;
- `/api/openapi.yaml` — исходную схему.

В Swagger UI сначала выполните `POST /hello` без Authorize: передайте имя сотрудника
в `client_id` и его персональный `token`. Из ответа скопируйте `session_token` в
**Authorize** без префикса `Bearer`. Затем раскройте рабочую операцию, заполните
параметры и нажмите **Execute**. Персональный токен в Authorize не подходит.
Запросы выполняются на том же HTTP/HTTPS-сервере, который открыл документацию.
`POST /hello` возвращает `client`, `session_token` и `expires_at`, но не заполняет
Authorize автоматически. Сессия по умолчанию действует `24h`; серверная настройка —
`session_ttl` или `--session-ttl`. После истечения срока повторите `/hello` и вручную
замените токен сессии в Authorize. Для смены сотрудника получите сессию через `/hello`
с его именем и персональным токеном, затем замените значение в Authorize.

Сессии хранятся в PostgreSQL; рабочие ручки проверяют срок, актуальную роль и
`enabled` при каждом запросе. Истёкшая сессия даёт `401`, даже если фоновая очистка
раз в `cache_refresh` ещё не удалила её запись. CLI выполняет рукопожатие при каждом
запуске команды и хранит сессию в памяти процесса. При `401` он один раз получает
новую сессию и повторяет запрос с исходными данными.

Для новой заметки задайте новый `request_id` и актуальный `event_at`.
Для повторной доставки сохраните прежний идентификатор и все поля запроса.
Примеры ID и времени в схеме иллюстративные. Идентификаторы созданных клиентов,
сюжетов и уведомлений берите из ответов сервера.

Файлы `swagger-ui-bundle.js` и `swagger-ui.css` скопированы без изменений из
[Swagger UI v5.33.3](https://github.com/swagger-api/swagger-ui/tree/v5.33.3/dist).
Условия распространения сохранены в `swagger-ui/LICENSE` и `swagger-ui/NOTICE`.
Обновляйте оба файла из одной версии вместе с лицензией и NOTICE.
При работе UI использует локальные ресурсы; CDN и внешний валидатор отключены.

Схема поддерживается вручную. Тест в `internal/httpapi/docs_test.go` сравнивает
описанные методы и пути с реальными маршрутами chi. После изменения схемы или
ресурсов пересоберите сервер.
