# Издание

Клиент-серверное приложение для задания № 6. Корреспонденты отправляют заметки,
сервер объединяет их в сюжеты и публикует новости, когда подтверждений достаточно.
Редактор управляет сотрудниками и смотрит статистику. Работать можно через
**CLI — программу в терминале — или HTTP API со Swagger**.

## Быстрый запуск и первый редактор

Понадобятся **Go 1.22+, Docker с Compose v2+ и Make**. Запустите Docker.
Все команды ниже выполняются из корня проекта в Linux, macOS или WSL.
При первом запуске нужен интернет для загрузки зависимостей и образа PostgreSQL.

**1. Впишите своё имя** в [configuration/editor.name](configuration/editor.name).
В файле должна быть одна строка, например:

```text
artem
```

Можно оставить `editor`. Имя выбирается перед первой настройкой;
`tonny` и `sacharissa` заняты демонстрационными корреспондентами.

**2. Запустите весь сервис одной командой:**

```bash
make demo
```

Команда подготовит локальные конфиги, запустит PostgreSQL через Docker Compose,
соберёт сервер и клиент в `bin/`, затем запустит сервер. База работает в Docker,
а Go-сервер и CLI — на вашей машине. Таблицы создаются автоматически.

**Сам сервер создаст редактора, сгенерирует персональный токен и выведет его
в терминале. Сохраните этот токен.** Сервер также запишет его в
`.times-demo/editor.token`; скрипт настройки токены не генерирует.

**3. Откройте второй терминал и войдите редактором:**

```bash
bin/times --config .times-demo/editor.local.yaml connect
```

Клиент сам прочитает токен из файла. В ответе будут ваше имя и `role: "editor"`.
Показать сохранённый сервером токен отдельно можно командой `make editor-token`.
Файлы `editor.local.yaml` и `editor.token` сохраняют эти названия при любом имени пользователя.

В демозапуске доступны три учётные записи:

| Пользователь | Роль | Конфиг CLI |
|---|---|---|
| Ваше имя из `configuration/editor.name` | Редактор | `.times-demo/editor.local.yaml` |
| `tonny` | Внештатный корреспондент, доверие 0.25 | `.times-demo/tonny.local.yaml` |
| `sacharissa` | Штатный корреспондент, доверие 1 | `.times-demo/sacharissa.local.yaml` |

**Остановка:** Ctrl+C завершает сервер, `make db-stop` останавливает PostgreSQL.
Повторный `make demo` использует существующие настройки, токены и данные.
База хранится в Docker volume; конфиги, токены и очереди клиента — в `.times-demo/`.
Локальный каталог исключён из Git, шаблоны и скрипт настройки входят в репозиторий.

## Swagger и адреса

После запуска доступны:

- [Swagger UI — описание и вызов API](http://127.0.0.1:8080/docs).
- [Состояние HTTP-сервера](http://127.0.0.1:8080/healthz).

Сервер по умолчанию слушает `127.0.0.1:8080`, PostgreSQL — `127.0.0.1:54329`.
Для подключения к демобазе имя базы, пользователь и пароль — `times`.

## Какие конфиги менять

Для обычного запуска достаточно изменить имя редактора. Чтобы заранее настроить
порт, правила публикации или срок сессии, сначала выполните `make init`,
отредактируйте созданные файлы и затем запустите `make demo`.
`make init` готовит только конфиги; пользователей и токены создаёт сервер.

| Файл | Что в нём менять |
|---|---|
| [configuration/editor.name](configuration/editor.name) | Имя первого редактора **до первого `make init` или `make demo`** |
| `.times-demo/server.local.yaml` | Адрес сервера, подключение к БД, правила публикации, сессии и TLS |
| `.times-demo/editor.local.yaml` | Адрес сервера и настройки клиента редактора |
| `.times-demo/tonny.local.yaml`, `.times-demo/sacharissa.local.yaml` | Настройки клиентов корреспондентов |
| [compose.yaml](compose.yaml) | Порт и параметры PostgreSQL, который запускает Docker |

Например, при смене порта сервера на `8090` задайте `addr: 127.0.0.1:8090`
в серверном конфиге и `server: http://127.0.0.1:8090` в используемых клиентских.
После изменения серверных настроек перезапустите сервер. Если изменили параметры
PostgreSQL в Compose, согласуйте с ними `database_url` сервера.

Первоначальный список `clients` создаёт отсутствующих сотрудников.
Для существующей учётной записи используйте прежний конфиг; управление доверением
и доступом выполняется командами CLI. Дополнительного редактора создавайте через
`clients create`, как показано ниже.

## Настройки сервера и клиента

Основные поля серверного YAML:

| Поле | По умолчанию | Назначение |
|---|---|---|
| `addr` | `127.0.0.1:8080` | Адрес и порт HTTP-сервера |
| `database_url` | PostgreSQL на `127.0.0.1:54329`, база `times` | Строка подключения к БД |
| `threshold` | `1.1` | Минимальная сумма доверия для публикации |
| `half_life` | `6h` | Время, за которое вес сообщения уменьшается вдвое |
| `congratulate` | `3` | Сколько первых авторов получат поздравление; `0` отключает их |
| `session_ttl` | `24h` | Срок действия сессии после входа |
| `cache_refresh` | `5m` | Период обновления кеша и очистки истёкших сессий |
| `tls_cert_file`, `tls_key_file` | Пустые строки | Пути к сертификату и приватному ключу для HTTPS |

**TLS по умолчанию выключен.** Для HTTPS задайте оба пути, перезапустите сервер
и замените `http://` на `https://` в адресе клиента. Сертификат должен быть доверенным
для клиента и соответствовать имени сервера. Для отключения очистите оба поля.

Настройки можно переопределить флагами: например,
`bin/times-server --config .times-demo/server.local.yaml --session-ttl 48h`.
Основные флаги: `--addr`, `--database-url`, `--threshold`, `--half-life`,
`--congratulate`, `--session-ttl`, `--cache-refresh`.
Приоритет: **явно переданный флаг → YAML → значение по умолчанию**.

В конфиге клиента `server` — адрес сервера, `client_id` — **имя для входа**,
`token_file` — файл персонального токена, `state_dir` — каталог сохранённых
запросов, `request_timeout` — время ожидания ответа (по умолчанию `20s`).
Токен CLI выбирается в порядке `--token` → `TIMES_CLI_TOKEN` → файл токена → YAML.
Если ранее задали `TIMES_CLI_TOKEN`, уберите её через `unset TIMES_CLI_TOKEN`,
чтобы клиент использовал токен выбранной учётной записи из файла.

## Команды CLI

Общий вид: `bin/times --config <конфиг клиента> <команда>`.
В таблице указана часть после пути к конфигу. Ответы выводятся в JSON.

| Команда | Что делает | Кому доступна |
|---|---|---|
| `connect` | Входит и забирает накопленные поздравления | Всем сотрудникам |
| `connect --no-ack` | Получает поздравления без подтверждения получения | Всем сотрудникам |
| `note send --rubric "Рубрика" --topic "Тема" --body "Текст"` | Отправляет заметку | Всем сотрудникам |
| `note pending` | Показывает локально сохранённые запросы | Локальная команда |
| `note retry <request-id>` / `note retry --all` | Повторяет один сохранённый запрос / все запросы текущего пользователя к этому серверу | Всем сотрудникам |
| `stories` / `stories <story-id>` | Показывает сюжеты / сюжет с порядком участников | Всем сотрудникам |
| `notifications` | Получает и подтверждает поздравления | Всем сотрудникам |
| `stats` | Показывает личную статистику | Всем сотрудникам |
| `stats --all` | Показывает статистику всех сотрудников | Редактору |
| `clients list` | Показывает сотрудников и их числовые ID | Редактору |
| `clients create --name ivan --kind freelance --role reporter --trust 0.4` | Создаёт сотрудника; сервер выдаёт его персональный токен | Редактору |
| `clients trust <id> --trust 0.5` | Меняет доверие к сотруднику | Редактору |
| `clients enabled <id> --enabled=false` | Отключает доступ; `true` включает его обратно | Редактору |

У `note send` обязательны `--rubric` и `--topic`. Время события по умолчанию —
текущее; своё можно передать через `--event-at` в формате RFC3339.
У `notifications` есть `--limit` (по умолчанию 100, максимум 1000) и `--no-ack`.
CLI сам выполняет вход перед запросами к серверу; отдельный `connect` необязателен.

Чтобы добавить **ещё одного редактора**, выполните от имени действующего:

```bash
bin/times --config .times-demo/editor.local.yaml clients create \
  --name reviewer --kind staff --role editor
```

Сервер вернёт данные сотрудника и `token`. Для его входа скопируйте шаблон клиента
в отдельный локальный файл, задайте `client_id: reviewer`,
`token_file: .times-demo/reviewer.token` и `state_dir: .times-demo/reviewer-state`.
В указанный файл токена сохраните только строку, выданную сервером.

`role` задаёт права (`editor` или `reporter`), `kind` — тип источника (`staff` или
`freelance`). Доверие задаётся от 0 до 1; без явного `--trust` штатный сотрудник
получает 1, внештатный — 0.25. В командах управления `<id>` — числовой ID из
`clients list`, а не имя для входа.

Справка по всем параметрам: `bin/times --help`, по отдельной команде —
например, `bin/times note send --help`.

## Что реализовано внутри

- **Публикация по доверию.** Одинаковые рубрика и тема образуют сюжет. До публикации
  учитывается первая заметка каждого автора. Вес зависит от доверия к нему и возраста
  сообщения. При приёме заметки сервер проверяет сумму и публикует сюжет, если она
  не меньше порога. Места фиксируются по порядку приёма заметок. Статистика отражает
  публикации, первые места и средний ранг.
- **Защита от повторов и одновременных запросов.** У заметки есть идентификатор запроса.
  Повторная доставка не создаёт вторую запись. Транзакции и блокировки PostgreSQL
  позволяют сохранить заметку, публикацию, места и поздравления вместе.
- **Сессии и права.** Сервер генерирует персональные токены, а в БД хранит их SHA-256-хеши.
  Вход через `/hello` выдаёт отдельный сессионный токен. Срок сессии, роль и доступ
  сотрудника проверяются при запросах; CLI умеет обновлять истёкшую сессию.
- **Повторная доставка.** Перед отправкой подготовленного запроса CLI сохраняет его
  на диск и удаляет после квитанции. Поздравления хранятся на сервере до подтверждения
  получения, поэтому их можно забрать после переподключения.
- **Кеш и фоновые задачи.** Данные клиентов и сюжетов кешируются; затронутые записи
  кеша сбрасываются после изменений. Фоновые задачи обновляют кеш и очищают истёкшие сессии.
- **Готовность к запуску.** Миграции БД применяются автоматически. Swagger встроен
  в бинарник и работает без внешнего CDN. Есть unit- и интеграционные тесты,
  включая конкурентную публикацию, сессии, повторные запросы и откат транзакций.

## Технологии и структура

| Технология | Для чего используется |
|---|---|
| Go 1.22+, `net/http`, Chi | HTTP-сервер и маршруты API |
| PostgreSQL 17, pgx | Хранение данных, пул соединений, транзакции и блокировки |
| Squirrel | Построение SQL-запросов с параметрами |
| Cobra, pflag, YAML | Команды CLI, флаги и конфиги |
| OpenAPI 3.0.3, Swagger UI | Описание API и интерфейс в браузере |
| Docker Compose, Make | Запуск БД, сборка и проверки |

`cmd/` — точки входа; `configuration/` — запуск и настройки;
`internal/cli` и `internal/httpapi` — клиент и HTTP;
`internal/service` — правила работы сервиса; `internal/store` — доступ к БД;
`internal/cache` и `internal/jobs` — кеш и фоновые задачи;
`migrations/` — миграции; `api/` — схема API и Swagger.

## Команды Make

| Команда | Действие |
|---|---|
| `make demo` | Готовит конфиги, запускает БД, собирает и запускает сервер |
| `make init` | Готовит только локальные конфиги |
| `make editor-token` | Показывает копию токена, выданного сервером при демозапуске |
| `make build` | Собирает `bin/times` и `bin/times-server` |
| `make db-up` / `make db-stop` | Запускает / останавливает PostgreSQL с сохранением данных |
| `make run` | Запускает сервер через `go run` с `configuration/server/config.yaml`; в нём по умолчанию нет сотрудников |
| `make test` / `make vet` | Запускает unit-тесты / статический анализ |
| `make test-integration TEST_DATABASE_URL='postgres://times:times@127.0.0.1:54329/times?sslmode=disable'` | Запускает тесты с PostgreSQL и проверкой гонок; БД должна быть запущена |
